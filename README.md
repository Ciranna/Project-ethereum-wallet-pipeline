
# Ethereum Wallet Pipeline

An interactive educational web application that demonstrates
Ethereum wallet key derivation, cryptographic primitives,
and the avalanche effect of Keccak-256.

The project is implemented using vanilla JavaScript,
HTML, CSS, and Vite.

## 1. Project Overview

The application consists of three main sections:

1. Interactive Wallet Pipeline
2. Statistical Exploration
3. Scientific Conclusions

The goal is to explain how an Ethereum wallet address
can be derived from a BIP-39 mnemonic and to investigate
the avalanche effect of the Keccak-256 hash function.

## 2. Interactive Wallet Pipeline

The application implements five sequential stages.

### Stage 1 — BIP-39

Converts a mnemonic phrase into a 512-bit seed using:

- PBKDF2-HMAC-SHA512
- 2048 iterations
- Unicode NFKD normalization

### Stage 2 — BIP-32 / BIP-44

Derives the hierarchical deterministic wallet keys.

Ethereum derivation path:

    m/44'/60'/0'/0/0

The application displays:

- Master private key
- Master chain code
- Ethereum account private key

### Stage 3 — secp256k1

Generates the public key through elliptic-curve
scalar multiplication:

    Q = kG

The application displays compressed, uncompressed,
and Ethereum-format public keys.

### Stage 4 — Keccak-256

Hashes the 64-byte Ethereum public key.

The Ethereum address is obtained from the final
20 bytes of the Keccak-256 digest.

### Stage 5 — EIP-55

Applies mixed-case checksum encoding to the
Ethereum address and verifies the checksum.

## 3. Statistical Exploration

The application investigates the avalanche effect
of Keccak-256.

An experiment:

1. Encodes a text input as UTF-8.
2. Computes its original Keccak-256 hash.
3. Flips exactly one input bit.
4. Computes the modified hash.
5. Calculates the Hamming distance between the hashes.
6. Calculates the percentage of changed output bits.

The Hamming distance is:

    D(H1, H2) = number of differing bits

The avalanche percentage is:

    Avalanche (%) = D(H1, H2) / 256 * 100

### Single-Bit Experiment

Displays:

- Number of modified input bits
- Number of changed output bits
- Avalanche percentage
- Original 256-bit hash
- Modified 256-bit hash
- XOR difference visualization

### Full Avalanche Analysis

Repeats the experiment for every input bit.

The application calculates:

- Total experiments
- Average changed output bits
- Average avalanche percentage
- Minimum Hamming distance
- Maximum Hamming distance

A bar chart displays the Hamming distance for
each modified input bit.

A horizontal reference line indicates the
theoretical expectation of 128 changed bits (50%).

## 4. Experimental Results

For the input "Ethereum":

- Input length: 8 bytes (64 bits)
- Experiments: 64
- Average changed bits: 129.3125
- Average avalanche percentage: 50.5127%
- Minimum changed bits: 108
- Maximum changed bits: 152

These observations are consistent with the expected
avalanche behavior of a cryptographic hash function.

However, they do not establish the overall
cryptographic security of Keccak-256.

## 6. Installation

Requirements:

- Node.js compatible with Vite 8
- npm

Clone the repository:

    git clone <REPOSITORY_URL>
    cd ethereum-wallet-pipeline

Install dependencies:

    npm install

Start the development server:

    npm run dev

Build for production:

    npm run build

Preview the production build:

    npm run preview

Run automated tests:

    npm test

## 8. Security Notice

This application is intended exclusively for
educational purposes.

It uses a fixed, publicly known mnemonic test vector.

Never enter a real wallet recovery phrase or use
keys generated by this demonstration to store funds.

The application is not intended to be a production
cryptocurrency wallet.

## 9. Scientific Limitations

The avalanche experiment evaluates how changes
in input bits affect the Keccak-256 output.

A result close to 50% is consistent with the
expected behavior of an ideal hash function.

However, avalanche measurements alone cannot prove:

- Collision resistance
- Preimage resistance
- Second-preimage resistance
- Overall cryptographic security

The statistical results depend on the selected input
and the number of experiments performed.
